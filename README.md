# Индексирование и поиск

Хранение записей студентов, индексирование простых и составных атрибутов, сравнение линейного, древесного и бинарного поиска.

Используются `BinarySearchTree`, `DynamicArray` и модель `Student` из [AD3](https://github.com/VenEraBle842/AD3). CMake загружает зависимость автоматически на зафиксированной ревизии.

## Возможности

- `TreeDictionary<Key, Value>` и `SortedArrayDictionary<Key, Value>` реализуют общий `IDictionary` на дереве и отсортированном массиве.
- `ArraySortedSequence<T, Compare>` реализует `ISortedSequence` на динамическом массиве.
- Алгоритмы `lowerBound`, `upperBound`, `binarySearch` и `equalRange`.
- Обобщенный `StudentIndex<Key, Compare>` по ID, фамилии, году рождения, GPA и составному ключу «фамилия, имя, год рождения»; выборочное построение и отдельная актуальность каждого индекса.
- Точный поиск тремя стратегиями; включительный диапазонный поиск по году, GPA и составному ключу — линейной и бинарной стратегиями.
- Хранение в структурированном текстовом файле с проверкой данных при загрузке и сохранением через временный файл.
- Графический интерфейс wxWidgets и консольное меню, общий каталог ошибок, проверяемый бенчмарк с CSV и скрипт построения графиков.

Исходные записи не переставляются: индексы хранятся отдельно и ссылаются на студентов через позицию, ID и идентификатор снимка. ID должен быть уникальным, GPA — конечным числом. После изменения данных индексированный запрос требует перестроения выбранного индекса; линейный поиск доступен сразу. Актуальность определяется идентификатором снимка данных.

Дерево не балансируется: поиск занимает $O(h)$, в худшем случае $O(N)$. Бинарные границы находятся за $O(\log N)$, выдача $K$ совпадений требует еще $O(K)$. Построение индексов в худшем случае занимает $O(N^2)$ из-за вставок в дерево и сдвигов в массиве.

## Структура проекта

| Каталог | Содержимое |
| --- | --- |
| `include/dictionary/`, `include/sequence/` | Интерфейсы и реализации словаря и отсортированной последовательности |
| `include/search/`, `include/common/` | Бинарный поиск, сортировка, концепты, ошибки и `TwoElement` |
| `include/models/`, `include/index/` | Составной ключ и каталог индексов |
| `include/storage/`, `include/service/` | Репозиторий, файловое хранилище и сервис поиска |
| `include/application/`, `src/student_application.cpp` | Общие сценарии приложения и запросы поиска для обоих интерфейсов |
| `include/gui/`, `src/gui/` | Графический интерфейс и последовательное выполнение фоновых операций |
| `src/` | Консольное приложение, реализация каталога, файловых операций и бенчмарка |
| `tests/` | Модульные и интеграционные тесты GoogleTest |
| `benchmark/` | Точка входа бенчмарка и скрипт графиков |

Шаблонные структуры и алгоритмы реализованы в заголовочных файлах. `StudentSearchService` объединяет репозиторий исходных записей и каталог индексов.

`StudentIndexCatalog` хранит реестр сочетаний атрибута и структуры в `DynamicArray`. Регистрация не строит индекс. Один `StudentIndex<Key, Compare>` работает через `IDictionary<Key, StudentRecordReferences>` с любым из двух словарей.

Общие операции построения, состояния и копирования находятся в `IStudentIndexBase`. Поиск принимает ключ напрямую через шаблонные интерфейсы `IStudentIndex<Key>` и `IStudentRangeSearch<Key>`. `getIndex<Key>(selection)` проверяет тип индекса через `std::dynamic_pointer_cast` и возвращает `shared_ptr<const IStudentIndex<Key>>`; неизвестное сочетание или неподходящий тип дают пустой указатель. Копирование каталога глубоко копирует индексы.

Диапазонный поиск — отдельная возможность `IRangeDictionary` / `IStudentRangeSearch<Key>`, доступная у отсортированного словаря. `supportsRangeSearch()` проверяет ее наличие, `rangeSearch()` возвращает константную ссылку на интерфейс.

```cpp
service.buildIndexes({{SearchAttribute::BirthYear, IndexBackend::SortedArray}});
service.findByBirthYear(2003, ExactSearchStrategy::Binary); // массив ID
const auto records = service.findExact(studentBirthYearAttribute, 2003,
                                      ExactSearchStrategy::Binary);
// service.resolve((*records)[0]) — копия записи по позиции с проверкой снимка
```

Консоль и GUI используют `searchRecords`: отображение K совпадений занимает $O(K)$ без повторного поиска ID. Репозиторий хранит записи и идентификатор снимка; скрытого ID-индекса в нем нет. Добавление проверяет уникальность линейно, массовая замена — сортировкой временного массива ID за $O(N \log N)$, сохраняя исходный порядок записей.

`StudentAttribute<Key, Compare>` содержит единое описание атрибута: идентификатор, название, извлечение ключа, названия полей ввода, функцию разбора, поддержку диапазона и подсказку. Стандартные определения и их общий перечень находятся в `include/index/student_attributes.hpp`, функции разбора — в `src/student_attributes.cpp`. Каталог индексов и реестр поиска используют один `forEachStudentAttribute`.

Консоль и GUI получают описания из `SearchRequestHandlers::getAttributes`. Список диапазонных запросов фильтруется по `supportsRange`, а число полей формы определяется описанием. `SearchKeyInput` — собственный `DynamicArray<std::string>`; перед разбором проверяется количество полей. Для добавления стандартного атрибута достаточно описать его, добавить в общий перечень и реализовать разбор ключа. Отдельные списки атрибутов в интерфейсах менять не нужно.

`getIndexStatistics()` возвращает число записей и массив состояний всех зарегистрированных индексов: атрибут, структура, число ключей, признаки построения и устаревания. Статистика доступна и при выборочном построении; число ключей устаревшего индекса относится к его прежнему снимку. Общего перечня типов ключей нет: пользовательский ключ, например `TwoElement<std::string, int>`, регистрируется тем же способом со своим компаратором.

## Требования и сборка

- Компилятор и стандартная библиотека с поддержкой C++23.
- CMake 3.24 или новее, Make или Ninja.
- Git и доступ к GitHub для первой загрузки TreeSetLab.
- Установленный GoogleTest при включенных тестах.
- wxWidgets 3.2 или новее (компоненты `core` и `base`) при включенном GUI.
- Python 3 и `matplotlib` для графиков.

Из корня проекта:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel
```

| Цель | Назначение |
| --- | --- |
| `dor2` | Консольное приложение |
| `dor2_gui` | Графическое приложение |
| `dor2_tests` | Тесты |
| `dor2_benchmark` | Бенчмарк с экспортом CSV |

Параметры CMake: `DOR2_BUILD_TESTS`, `DOR2_BUILD_BENCHMARK` и `DOR2_BUILD_GUI` включены по умолчанию, `DOR2_ENABLE_SANITIZERS` выключен. GoogleTest ищется через `find_package` и автоматически не загружается. Для сборки без него укажите `-DDOR2_BUILD_TESTS=OFF`. Для консольной сборки без wxWidgets укажите `-DDOR2_BUILD_GUI=OFF`. Зависимость от wxWidgets есть только у графических целей.

## Единая обработка ошибок

`include/common/error_catalog.def` — единый каталог кодов, сообщений и подсказок. Из него автоматически формируются `ErrorCode` и таблица описаний. `Error` содержит код и контекст: поле, путь, строку файла, подробности. Ожидаемые ошибки возвращаются через `std::expected`; неожиданные исключения перехватываются на границе выполнения команд.

Для добавления ошибки:

1. Добавьте строку в каталог, например:

   ```cpp
   DOR2_ERROR(InvalidStudentName, "Invalid student name.", "Check the name and try again.")
   ```

2. Верните ее из операции:

   ```cpp
   return std::unexpected(makeError(ErrorCode::InvalidStudentName,
       {.field = "First name", .detail = "Additional diagnostic information"}));
   ```

Словарь, последовательность, репозиторий, индексы, сервис поиска, файловое хранилище, бенчмарк и прикладной слой возвращают ожидаемые ошибки в едином формате `std::expected<T, Error>`. Код и описание новой ошибки добавляются только в общий каталог; в месте обнаружения используется `makeError(ErrorCode::..., context)`. Промежуточных enum и структур ошибок, а также преобразований между слоями нет. При передаче ошибки выше сохраняется весь её контекст, а при необходимости дополняется.

Обработчики GUI и консоли менять не нужно: оба используют `formatError`. Числовой ввод обоих интерфейсов проверяется общими `parseNumber` и `parseBoundedSize` с классической локалью. Неожиданные исключения по-прежнему перехватываются на границе выполнения команд и показываются как `ErrorCode::Unexpected`.

## Консольное приложение

```bash
./build/dor2
```

Интерфейс на английском языке.

| Пункт | Действие |
| ---: | --- |
| `1` | Добавить студента |
| `2` | Заменить данные сгенерированным набором |
| `3` | Показать исходные записи |
| `4`, `5` | Загрузить / сохранить файл |
| `6`, `7` | Построить выбранные индексы / показать состояния и статистику |
| `8` | Точный поиск по зарегистрированному атрибуту |
| `9` | Диапазонный поиск по поддерживающему его атрибуту |
| `10` | Точный или диапазонный поиск по ключу с несколькими полями |
| `11`, `12` | Сравнить алгоритмы / экспортировать последнее сравнение в CSV |
| `0` | Завершить программу |

В поиске сначала выбираются атрибут и стратегия, затем вводятся поля, перечисленные в описании атрибута. Для диапазона вводятся оба ключа целиком. Пункт `10` использует тот же сценарий, оставляя только атрибуты с несколькими полями.

После добавления или генерации данных выберите `6` перед древесным или бинарным поиском. Введите номера нужных сочетаний атрибута и структуры через пробел; `0` строит все индексы. Не выбранные индексы сохраняют прежнее состояние. Загрузка файла автоматически перестраивает индексы; некорректный файл не заменяет текущие данные.

Составной диапазон задается двумя полными ключами и сравнивается лексикографически: сначала фамилия, затем имя, затем год. Например, диапазон от `(Smith, Anna, 2002)` до `(Smith, Ivan, 2004)` включает имена между `Anna` и `Ivan` независимо от года; год уточняет границу при совпадении фамилии и имени. Это не три независимых диапазона. Результаты упорядочены по ключу, затем по ID.

## Графическое приложение

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DDOR2_BUILD_GUI=ON
cmake --build build --parallel 2
./build/dor2_gui
```

Графический интерфейс поддерживает все действия консольного меню:

| Раздел GUI | Действия |
| --- | --- |
| `Students` | `Add student...`, `Generate data...`, таблица исходных записей, `Open...`, `Save as...` |
| `Search` | Выбор `Exact` / `Range`, атрибута, стратегии, значений или полных составных ключей; таблица совпадений |
| `Indexes` | Выбор сочетаний атрибута и структуры, `Build selected indexes`, состояние и число ключей каждого индекса |
| `Algorithm comparison` | Размер набора, число запросов, seed, `Run comparison`, таблица всех 21 измерений и `Export CSV...` |
| `File` | `Open...` (`Ctrl+O`), `Save as...` (`Ctrl+Shift+S`), `Exit` (`Ctrl+Q`) |

Пример: откройте `Students` &rarr; `Generate data...`, задайте 1000 записей и seed 100. Затем в `Indexes` отметьте нужные индексы и нажмите `Build selected indexes` (изначально выбраны все). В `Search` выберите `Exact`, `ID`, `Tree`, введите `1000` и нажмите `Search`. Для диапазона выберите `Range`, `Birth year`, задайте нижнюю и верхнюю границы, например 2000 и 2004. Для составного ключа первое поле — фамилия, далее имя и год рождения; при диапазонном поиске заполняются оба полных ключа.

Строка состояния показывает количество записей и число актуальных индексов, например `2/10 ready`. В разделе `Indexes` каждое сочетание отдельно имеет состояние `not built`, `out of date` или `ready`. После добавления или генерации данных перестройте индексы перед древесным или бинарным поиском. Линейный поиск доступен сразу. Пустая выдача — успешный результат `Matches: 0`.

Загрузка сначала проверяет файл и строит индексы во временном состоянии; только после успеха заменяет текущие записи. При замене непустого набора требуется подтверждение. При закрытии с несохраненными записями показывается предупреждение. Сравнение алгоритмов использует отдельный набор и не меняет студентов в таблице.

Операции выполняются последовательно в рабочем потоке. Пока операция выполняется, формы и открытие/сохранение недоступны; окно продолжает обрабатывать события. GUI получает копию готового состояния и не обращается к репозиторию одновременно с рабочим потоком. Закрытие во время операции откладывается до ее завершения; прерывание посередине операции не предусмотрено. Таблицы студентов и совпадений запрашивают текст видимых строк по мере необходимости.

## Формат данных

```text
DOR2_STUDENT_DATA 1
2
101:"Ivan":"Ivanov":2003:4.8
102:"Anna":"Petrova":2002:4.5
```

Первая строка — сигнатура и версия формата, вторая — число записей. Далее идут поля `id:"firstName":"lastName":birthYear:gpa`. Строки обязательны в двойных кавычках; пробелы, двоеточия, кавычки и обратные слеши поддерживаются через `std::quoted`. Десятичный разделитель — точка.

Загрузка проверяет формат, количество записей, уникальность ID и конечность GPA. Индексы в файл не записываются. Сохранение сначала записывает `<имя файла>.tmp` и заменяет целевой файл после успешного завершения записи.

## Тесты

```bash
ctest --test-dir build --output-on-failure
```

Проверяются общий контракт обоих словарей и последовательность, бинарные границы, точный и диапазонный поиск, одинаковые ключи и порядок результатов, единое описание атрибутов, произвольное число полей ключа, выборочное построение и статистика всех состояний индексов, независимость их копий, зарегистрированные обработчики, ссылки на записи и снимки после копирования и перемещения, файловый формат и интеграционный цикл загрузки, поиска и сохранения. Бенчмарк проверяется на небольшом наборе.

Тесты прикладного слоя дополнительно проверяют общий числовой ввод, каталог ошибок и контекст, одинаковые запросы обоих интерфейсов, воспроизводимую генерацию, сохранность данных при неудачной загрузке, кириллицу в данных и пути, сохранение последних результатов при неудачном сравнении и экспорт CSV.

Для проверки AddressSanitizer и UndefinedBehaviorSanitizer:

```bash
cmake -S . -B build-sanitize -DCMAKE_BUILD_TYPE=Debug -DDOR2_ENABLE_SANITIZERS=ON
cmake --build build-sanitize --parallel
ctest --test-dir build-sanitize --output-on-failure
```

Если среда сообщает, что LeakSanitizer не работает под `ptrace`, добавьте `ASAN_OPTIONS=detect_leaks=0` перед командами сборки и запуска тестов. ASan и UBSan продолжат работать, проверка утечек будет отключена.

## Бенчмарк и график

Для измерений используйте Release-сборку. Запускайте бенчмарк из корня проекта:

```bash
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release -DDOR2_BUILD_TESTS=OFF
cmake --build build-release --parallel
./build-release/dor2_benchmark
```

По умолчанию: 1000 записей, 200 запросов, seed `100`, результат — `benchmark_results.csv`. Другие размеры и seed доступны в пункте `11` меню. Измеряется построение `TreeDictionary` и `SortedArrayDictionary`, точный и диапазонный поиск на возрастающих, убывающих и случайных входных данных. После прогрева берется медиана пяти повторов; результаты стратегий предварительно сравниваются по полным спискам ID. CSV содержит 21 измерение и столбец `Verified`.

Для графика с отдельными панелями построения, точного и диапазонного поиска:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install matplotlib
.venv/bin/python benchmark/plot_results.py benchmark_results.csv benchmark_plot.png
```
